# RFCs — Requests for Comments

This folder holds accepted RFCs (Requests for Comments) that document
significant decisions about MEVDAN's architecture, APIs, or direction.

## What is an RFC?

An RFC is a design document for a substantial change:

- New crates
- Architectural changes
- Breaking API changes
- New formats or protocols
- Significant features

Small changes (bug fixes, docs, tests) do not need an RFC.

## Process

1. Open an issue with the `[RFC]` prefix in the title.
2. Describe the proposal in detail.
3. Discussion period of at least 7 days.
4. The maintainer accepts, requests changes, or rejects.
5. If accepted, the RFC is stored here as `NNNN-short-title.md`.

## Naming convention

```

NNNN-short-title.md

```

Where `NNNN` is a zero-padded number starting at `0001`.

## Format

Each RFC should include:

- **Title**
- **Status:** Proposed / Accepted / Rejected / Superseded
- **Date**
- **Context:** what problem are we solving?
- **Decision:** what are we doing?
- **Alternatives considered**
- **Consequences:** what changes as a result?
